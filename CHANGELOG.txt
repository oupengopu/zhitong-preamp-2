﻿v2.1.15 - 2026-07-10
  修复: 防火爆音机制失效 - 静音/待机/输出切换仍是硬切无渐变
  根因: 三条路径的渐变到零机制都有bug：
    A. soft_mute_switch turn_on_action: pga2311::set_volume(0,0) 在渐变开始后立即执行，
       截断了 send_volume_to_pga 的 while 循环(只跑了1步15ms就跳零)
    B. enter_standby/volume_fade_to_zero: 调用 send_volume_to_pga 时 soft_mute==false，
       其初始 lambda 的 else 分支把 target_db 覆盖回音量水平，渐变根本不跑
    C. switch_output_mode: 同 B + timeout:1200ms 太短(完整渐变需~2.8s)
  措施:
    - soft_mute_switch turn_on_action: 在 send_volume_to_pga 后加 wait_until
      current_db<=-95.5, timeout:8000ms，等渐变完成再硬件静音
    - volume_fade_to_zero: 重写为自包含渐变循环，不再调用 send_volume_to_pga，
      独立控制 target_db=-96 和 while 循环
    - enter_standby: 移除 script.stop:send_volume_to_pga，timeout 2000ms→8000ms
    - switch_output_mode: 改用 volume_fade_to_zero，timeout 1200ms→8000ms
    - switch_input: timeout 1200ms→8000ms(已有 switching_input 保护免受 target_db 覆盖)
  涉及文件: 智能前级蓝牙2.0.yaml
v2.1.14 - 2026-07-10
  修复: 显式指定 mipi_spi SPI mode 0，修复 2026.6.4 默认 MODE3 导致 NV3007 黑屏
  根因: ESPHome 2026.6.4 中 mipi_spi CUSTOM 模型在无 CS 引脚时默认 SPI mode 变为 MODE3，
    NV3007 显示驱动需要 MODE0，SPI 时序不匹配导致初始化失败 -> 黑屏有背光。
  措施:
    - 在 display config 中显式添加 spi_mode: 0
    - 配合前次 NotoSansSC 字体 web 下载修复，2026.6.4 可正常运行

v2.1.12 - 2026-07-07
  修复: 防火爆音机制 - 静音/待机/变压器切换爆音
  备注: 首次编译卡 Building bootloader.bin 是正常现象
    - 根因: PlatformIO 首次构建需要下载完整的 ESP-IDF 工具链
      (xtensa-esp-elf-gcc/cmake/ninja 等 ~500MB), 下载+解压期间
      无进度输出, 视觉上表现为卡死
    - 处理方法: 工具链缓存后第二次编译即恢复正常速度。
      不要删除 .platformio 或 .esphome 目录下的缓存!
      删除缓存只会导致下次编译重新下载工具链, 再次经历无进度等待
    - 静音开启爆音: soft_mute turn_on_action 中在 send_volume_to_pga 与硬件静音之间
      插入 pga2311::set_volume(0, 0) 确保 DAC 输出归零
    - 待机切入(enter_standby): 在 power_transitioning 前加入软渐变静音
      (target_db=-96 → wait_until current_db<=-95.5)
    - 待机恢复(exit_standby): relay_out.turn_on() 前移到 mute_switch ON + 
      pga2311::set_volume(0,0) 之后执行，避开 switch_input 完成后已开声的阶段
    - 输出模式切换(switch_output_mode): 新增专用脚本，按 switch_input 的
      防火爆音序列执行: 软渐变→硬件归零→硬件静音→切继电器→取消静音→恢复音量
    - 设置页输出模式切换 case 10: 从直接 toggle relay_out 改为调用
      id(switch_output_mode)->execute()
